Modern Java 21 for this project

Smart Campus is written in Java 21. Java changed a lot after Java 8: records, pattern matching, sealed types, text blocks. This lesson teaches the parts you will read and write in every module, using the real code in shared-kernel.

1. Why Java 21

Java 21 is an LTS release ("long-term support"): it gets security fixes for many years, so companies build on it. Spring Boot 4, Spring Modulith 2 and the other libraries in this project all run on it. The version is set once, in the root pom.xml: <java.version>21</java.version> (see lesson 02).

Modern Java helps us write small, safe types. The project rules in SPEC-platform.md say:

  • Records for DTOs (data sent over HTTP), events and value objects.
  • Constructor injection only, and no Lombok (a library that writes code for you with annotations). Records already remove most of the boring code.
  • var only when the type is obvious.
  • Inject a Clock and never call Instant.now().

Think of these rules like building with checked bricks. Each brick (a record) tests itself when it is made. A broken brick can never get into the wall.

2. Records and immutability

A record is a short way to write a class that only carries data. You write the fields once, in the header. Java writes the rest: the constructor, one read method per field (eventId(), not getEventId()), equals, hashCode and toString.

public record DomainEvent<P>(
        UUID eventId, String type, int schemaVersion, Instant occurredAt, String aggregateId, P payload) {

    public DomainEvent {                                // compact constructor
        Objects.requireNonNull(eventId, "eventId");
        Objects.requireNonNull(type, "type");
        Objects.requireNonNull(occurredAt, "occurredAt");
        Objects.requireNonNull(aggregateId, "aggregateId");
        Objects.requireNonNull(payload, "payload");
        if (type.isBlank()) {
            throw new IllegalArgumentException("type must not be blank");
        }
        if (schemaVersion < 1) {
            throw new IllegalArgumentException("schemaVersion must be >= 1, but got " + schemaVersion);
        }
    }
}

The compact constructor

public DomainEvent { ... } has no parameter list. It is a compact constructor: it runs before the fields are set, with the parameters already in scope. This is where a record checks its rules. If a rule fails, it throws, and the object is never created. So an invalid DomainEvent cannot exist anywhere in the program.

A compact constructor can also change a value before it is stored. Money does this to fix the number of decimals:

public record Money(BigDecimal amount, Currency currency) {
    public Money {
        Objects.requireNonNull(amount, "amount");
        Objects.requireNonNull(currency, "currency");
        int decimals = currency.getDefaultFractionDigits();           // VND → 0, USD → 2
        try {
            amount = amount.setScale(decimals, RoundingMode.UNNECESSARY); // reassign the parameter
        } catch (ArithmeticException tooManyDecimals) {
            throw new IllegalArgumentException(...);
        }
    }
}

Typed ids: one tiny record per kind of id

Every id in Smart Campus is a UUID. But if every method takes a plain UUID, nothing stops you from passing a course id where a student id is expected. So each module writes small records that implement TypedId:

public record StudentId(UUID value) implements TypedId {
    public StudentId {
        Ids.requireId(value, "StudentId");   // a null id is never allowed
    }
}

void enroll(StudentId student, SectionId section) { … }
enroll(sectionId, studentId);                  // does not compile: good!

shared-kernel does not contain StudentId itself. Ids belong to their module (for example the planned identity module). The kernel only gives the interface and the Ids helper.

equals and hashCode for free

Two records are equal when all their fields are equal. This is called value equality, and it is what we want for value objects: two "1 000 VND" are the same money. Because Money stores every amount with the currency's scale, even 10.5 USD and 10.50 USD are equal (the test equalsIgnoresScale in MoneyTest proves it). Equal objects also get the same hashCode, so records work correctly as keys in a HashMap or items in a HashSet.

Immutability

Immutable means "cannot change after it is made". Record fields are final, and there are no setters. To "change" money, you make a new one: fee.plus(tax) returns a new Money. Immutable objects are safe to share between threads and between modules, because nobody can change them behind your back.

Records are only "shallowly" immutable If a record holds a List, the list itself can still be changed by whoever has it. Copy it in the compact constructor: items = List.copyOf(items);. List.copyOf makes an unmodifiable copy (and rejects null items).

3. Enums with fields

An enum is a fixed list of named values. In Java, each value can carry its own fields and methods, like a tiny class. We use this for lists that are known when the code is written and that the build should check.

public enum ProblemCode {
    INTERNAL_ERROR(500, "Internal error"),
    VALIDATION_FAILED(400, "Validation failed"),
    NOT_FOUND(404, "Not found"),
    CONFLICT(409, "Conflict"),
    RATE_LIMITED(429, "Rate limited");

    private final int status;
    private final String title;
    private final URI type;

    ProblemCode(int status, String title) {          // enum constructors are always private
        this.status = status;
        this.title = title;
        this.type = URI.create(TYPE_BASE + name().toLowerCase(Locale.ROOT).replace('_', '-'));
    }
}

Topics is the same idea with four fields per value: the Kafka topic name, the partition count, the key field and a replayable flag (REGISTRATION_REQUESTS("registration.requests", 12, "sectionId", false)). Useful built-in methods:

  • values() gives all constants. TopicsTest uses it to check there are exactly 5 topics.
  • name() gives the constant's name, e.g. "NOT_FOUND".
  • valueOf("NOT_FOUND") finds a constant by its name.

Why Locale.ROOT? Lower-casing depends on the language. In Turkish, "I" becomes a dotless "ı". Locale.ROOT gives the same result on every computer.

4. Pattern matching, switch, sealed types

Pattern matching for instanceof

Old Java needed a test and then a cast. Java 21 does both in one step and gives the result a name:

Old style

if (value instanceof TypedId) {
    TypedId id = (TypedId) value;
    return id.value().toString();
}

Java 21 (from Topics.keyOf)

return value instanceof TypedId id
        ? id.value().toString()
        : value.toString();

ProbeTopic.isProbeEvent in core-app uses the same pattern with &&: event instanceof DomainEvent<?> envelope && EVENT_TYPE.equals(envelope.type()). The name envelope exists only where the test is known to be true.

Switch expressions

A switch expression gives back a value. It uses arrows (->), so there is no fall-through and no break:

String hint = switch (code) {
    case NOT_FOUND -> "Check the id in the URL";
    case CONFLICT, RATE_LIMITED -> "Wait a moment and try again";
    default -> "Contact support with the traceId";
};

Sealed interfaces and record patterns

A sealed interface lists every class that may implement it. Nobody else can add one. Then the compiler knows all the cases, and a switch over it needs no default. If someone adds a new case later, every switch that forgets it stops compiling. That is a safety net for business rules.

A record pattern takes a record apart inside the case, so you get its fields directly. Here is an example in the style of the planned registration module (names may change):

public sealed interface SeatResult
        permits SeatResult.Confirmed, SeatResult.Waitlisted, SeatResult.Rejected {

    record Confirmed(UUID enrollmentId) implements SeatResult {}
    record Waitlisted(int position) implements SeatResult {}
    record Rejected(String reason) implements SeatResult {}
}

String message(SeatResult result) {
    return switch (result) {                                   // no default needed
        case SeatResult.Confirmed c -> "You got the seat!";
        case SeatResult.Waitlisted(int position) -> "You are number " + position + " on the waitlist";
        case SeatResult.Rejected(String reason) -> "Sorry: " + reason;
    };
}
When to use a sealed type Use it when an answer can be one of a few shapes, each with different data: a seat result, a payment outcome, a grade-import row that is valid or has errors. It is clearer than one class with many nullable fields and a "status" string.

5. Generics

Generics let one class work with many types, while the compiler still checks them. DomainEvent<P> has a type parameter P for the payload. DomainEvent<EnrollmentConfirmed> is an envelope whose payload() returns an EnrollmentConfirmed, with no cast.

You seeIt meansReal example
DomainEvent<P>A class with a type parameterDomainEvent.java
DomainEvent<?>"An envelope of some payload type; I don't care which"Topics.keyOf(DomainEvent<?> event)
Class<?>"Some class object"EventTypes: Map<String, Class<?>>
new DomainEvent<>(…)The "diamond": Java works out the typeOutboxProbeService.create

Type erasure: generic types exist only for the compiler. When the program runs, a DomainEvent<EnrollmentConfirmed> is just a DomainEvent. That is why a consumer reading JSON cannot know the payload class by itself. It reads the type text and asks EventTypes: "EnrollmentConfirmed" → EnrollmentConfirmed.class (lesson 08 shows why the envelope matters).

6. var, Optional, streams, text blocks

var

var lets Java work out the type of a local variable from the right side. Project rule: use it only when the type is obvious from that line.

OK

var accessor = component.getAccessor();   // from Topics
var events = new ArrayList<DomainEvent<?>>();

Not OK

var x = service.process(input);   // what is x?
var n = 10;                       // int? long? say it

Optional

Optional<T> is a box that holds one value or nothing. Use it as a return type when "not found" is a normal answer. It forces the caller to decide what to do when the box is empty. From CampusProblemHandler in platform-starter:

Optional<ProblemCode> known = forStatus(status.value());        // 404 → NOT_FOUND, 405 → empty
String code = known.map(Enum::name).orElseGet(() -> codeName(status));

Do not use Optional for fields or method parameters, and never call get() without checking. Use map, orElse, orElseGet or orElseThrow.

Streams

A stream is a pipeline over a collection: filter, change, collect. It reads like a sentence. From Topics.byName:

return Arrays.stream(values())
        .filter(t -> t.topicName.equals(topicName))
        .findFirst()                                               // Optional<Topics>
        .orElseThrow(() -> new IllegalArgumentException("Unknown topic '%s'".formatted(topicName)));

.toList() (Java 16+) ends a stream with an unmodifiable list. The problem handler uses it to build the list of invalid fields. t -> … is a lambda (a small function without a name), and Enum::name is a method reference (a short form of e -> e.name()).

Text blocks and formatted

A text block is a multi-line string between """. It is perfect for SQL, because you can keep the query readable:

private static final String FIND_UNFINISHED = """
        SELECT id, event_type, publication_date
        FROM platform.event_publication
        WHERE completion_date IS NULL
        ORDER BY publication_date
        """;

Java removes the common indentation for you. For values, the project uses "Course %s does not exist".formatted(id) everywhere. Never glue user input into SQL text: pass values as ? parameters (lesson 04).

7. Time: Instant, ZoneId, Clock

The java.time package has a type for each meaning of "time":

TypeMeaningSmart Campus use
InstantOne exact point on the world timeline, in UTCoccurredAt, created_at, TimeRange, JSON times
ZoneIdA time zone with its rules, e.g. Asia/Ho_Chi_MinhShowing times to students in Vietnam (UTC+7)
ZonedDateTimeAn instant seen in one zone"Class starts Monday 08:00 local time"
LocalDateA date with no time and no zoneSemester start date, birthday
DurationAn amount of timeretry-interval: 30s, class length

The rule: store and send Instant (UTC). Convert to Asia/Ho_Chi_Minh only at the edge, when you show a time or when a rule depends on the local day:

static final ZoneId CAMPUS_ZONE = ZoneId.of("Asia/Ho_Chi_Minh");

LocalDate today = LocalDate.ofInstant(clock.instant(), CAMPUS_ZONE);   // "today" in Vietnam
ZonedDateTime start = ZonedDateTime.of(2026, 9, 7, 8, 0, 0, 0, CAMPUS_ZONE);
Instant startUtc = start.toInstant();                                  // 2026-09-07T01:00:00Z

Why we inject a Clock

Instant.now() reads the real computer time. A test that uses it gets a different answer every run, and a rule like "registration closes at 17:00" cannot be tested at 09:00. So the spec says: ask Spring for a Clock in the constructor, and call clock.instant().

ProductionClockConfiguration makes one bean: Clock.systemUTC()
→
Your classtakes Clock clock in its constructor, calls clock.instant()
←
Testspass Clocks.fixedAt("2026-09-07T08:00:00Z"): same time every run
PingController(Clock clock, @Value("${spring.application.name}") String app, …) {
    this.clock = clock;
}

@GetMapping("/ping")
Ping ping() {
    return new Ping(app, version, clock.instant());   // never Instant.now()
}

PingControllerTest gives a fixed clock and can expect exactly "2026-09-07T08:00:00Z" in the JSON. Clocks.offset(base, Duration.ofHours(2)) moves a test clock forward to test "after the deadline".

8. Money and errors

BigDecimal for money

double stores numbers in binary, so 0.1 + 0.2 gives 0.30000000000000004. For money that is not acceptable. BigDecimal stores exact decimal numbers.

  • Create it from a string: new BigDecimal("0.1"). The constructor that takes a double copies the binary error in.
  • Scale = digits after the point. VND has 0, USD has 2.
  • BigDecimal.equals looks at the scale (10.5 ≠ 10.50); compareTo does not. Money avoids the trap by fixing the scale.
  • RoundingMode.UNNECESSARY means "never round; fail instead". Half a đồng does not exist, so Money.of("1000.5", "VND") throws.

Always use Money, never a bare BigDecimal, because an amount without a currency is a bug waiting to happen. plus refuses to add USD to VND.

Unchecked exceptions and CampusProblem

Java has two kinds of exceptions. Checked ones (like IOException) must be declared with throws or caught. Unchecked ones extend RuntimeException and can be thrown anywhere. Our business errors are unchecked:

throw new CampusProblem(ProblemCode.NOT_FOUND, "Course %s does not exist".formatted(id));

The platform-starter catches it and writes problem JSON with status 404, the code NOT_FOUND and a traceId (lesson 09). Value objects throw plain IllegalArgumentException (bad value) or NullPointerException (missing value). They stay plain Java and do not know about HTTP.

Objects.requireNonNull

Objects.requireNonNull(amount, "amount") returns the value if it is not null, and throws a NullPointerException with the message "amount" if it is. Failing early, at construction, with the field name, is far easier to debug than a crash ten calls later. Ids.requireId uses the form that takes a Supplier, so the message string is only built when it is needed.

10. Common mistakes

  • Calling Instant.now() or LocalDate.now(). Ask for a Clock instead. Without a clock argument, LocalDate.now() also uses the server's zone, which may not be Vietnam.
  • Using LocalDateTime for a moment in time. It has no zone, so "08:00" is not a real point on the timeline. Store Instant.
  • Using double or a bare BigDecimal for money. Use Money.
  • Checking rules outside the record. Put the check in the compact constructor, so no code path can skip it.
  • Passing plain UUIDs around. Use the module's typed id.
  • Adding a default to a switch over a sealed type. Then the compiler cannot warn you when a new case is added.
  • Catching an exception and doing nothing. Let it travel up to the problem handler, or turn it into a CampusProblem with a clear code.
  • Field injection or Lombok. Both are against the project rules. Write the constructor (records do it for you).

13. Test yourself

1. Why do the rules of DomainEvent live in the compact constructor and not in the code that publishes events?

The compact constructor runs every time an envelope is created, on every code path. So an invalid envelope can never exist, and no publisher can forget the check. A check in the publisher would have to be copied, and one copy would be forgotten.

2. Why does Money change the scale in its constructor?

So that the same amount always has the same form (10.50 USD). Then the record's generated equals and hashCode work, even though plain BigDecimal.equals sees 10.5 and 10.50 as different.

3. What do we gain from StudentId instead of a plain UUID?

The compiler catches mixed-up ids. enroll(sectionId, studentId) with the arguments swapped does not compile. With plain UUIDs, it would compile and corrupt data.

4. Why must production code take a Clock instead of calling Instant.now()?

So tests can control time. With a fixed clock, a test gets the same result on every run and can check rules like "the window is closed after 17:00" at any time of day.

5. Why is a default branch a bad idea in a switch over a sealed interface?

Without default, the compiler checks that every case is handled. When someone adds a new case, every switch that misses it fails to compile. A default hides the new case silently.

6. Why does EventTypes exist, if DomainEvent is already generic?

Because of type erasure: at runtime the payload type is gone, and JSON contains no Java classes. The consumer reads the type text and needs a table to find the payload class to build.
